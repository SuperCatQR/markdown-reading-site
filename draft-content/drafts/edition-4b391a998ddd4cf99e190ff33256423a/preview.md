# 【行动计划】我们打算做一个什么样的网站（1）——初步功能

介绍一下这个网站。这个网站是我们做的一个项目展示平台，目前还没有备案，暂时只做了一个示例。目前的域名是 ismister\.cn，但后面备案成功后，应该会把这个‘主义主义’的 imismist（i\-m\-i\-s\-m\-i\-s\-t）改成 ismism（i\-s\-m\-i\-s\-m），也就是‘主义主义\.cn’。这些域名我们都已经注册掉了。

目前这个网站初步只用于活动公示，下面会有项目。现在还没有其他社群，互动的模块也还没做，所以暂时只做项目进度的公示。

我今天做这个视频也是一石二鸟，同时也是做出来告诉程序员、我们的技术同志接下来怎么干。我希望把项目的状况在 UI 层面做成一个血条，预算收到的支持可以放在边上，就相当于给它充血。

项目类别方面，当前支出要有一个详细的项目类别，可以点进去查看，里面各式各样的内容都是示例。还可以点‘查看票据’，但这个词还没有做出来，现在点了会转到百度网盘。

我还需要一个功能，就是显示支出是谁支出的，也就是这个项目的参与者、他的小团队、他的 team。比如我点进活动，紧跟着显示当前正处于哪个环节。这个环节可以用表的形式，相当于一条进度线，上面标明哪个环节正在进行中，而且这些环节都有人名。

这里有四个进度条。前面已经有一个血条，这里则是一个进度链条，显示项目做到什么程度。有点像你的快递的进度，但不能说它是进度条，而是一个进度列表。

这里面都有人员信息的公示，点进去都能看到。而且这些人员都是在我这个网站里注册的用户，会有自己的账号。你做了这个东西，就会有个终身成就：你是这个项目哪个环节的参与者，就有个项目经历在这里面，参与下一个项目的时候就会不一样。

比如刷油漆，我们有一个黑格尔主义者，到时候安排他过来刷油漆，两个厕所的油漆由他来刷。那么刷油漆的执行人就是他。这里分执行人和监督人，一个是执行者，一个是监督者，也就是执行层面和监督层面。

决策也要公示吗？这个就不公示了吧。如果每个项目的决策者都公示，最后拍板的肯定是我。但我不可能等摊子铺大了，所有项目都由我来拍板，肯定会有个决策机制，只是不需要公示。公示的话，就把执行者，包括买任何东西是谁执行的、谁监督的，都更新上去。

我们主要是要把项目和人员比较实时地对应起来，责任落实到人，状况落实到人，也把这个事情本身的功劳落实到人。这个人有这个功劳，都在这里可查，那你就是倍儿有面。在这活动公司里面，是不是？

另外一方面，把它做成一个相册，不要只有一张图。点进去之后，一个项目……而且项目应该是堆叠的。星星家园应当是一个长期的大项目，因为它下面不仅是扩建一个小项目。我们不要把所有的项目都以钱的形式呈现。有的项目，比如星星家园要参加九九公益日的筹款，也是我们团队要执行的项目。

所有这些子项目都包含在大项目星星家园下面：星星家园扩建、星星家园长期资助、星星家园志愿者参与进去帮孩子们搞一些活动专题，还有星星家园的一些其他项目。我说了，募捐、募款就不叫募款了，我们替他去打广告，我们是自媒体从业者，替他打广告。下面有几个子类，但它们的性质肯定不一样：有的是直接人去干活就行，有的是又要有钱又要有人，有的是帮他到外面要钱。相当于我们替他做广告，这种既不需要出人，也不需要出钱，只要帮他们做宣传。

还有的需要常设，不需要很多人，只需要在常设点有一两个人专门负责，比如物资或耗材上的，像他的晚餐。把这些分分类，解决他平时的一些小开支，解决他长期的场所改造，解决他长期对人员活动多样性的需求，解决他的募款需求。每一个页面可以用不同颜色显示，绿色、蓝色、红色、黄色，分成几类。最好上面有一个大标题，下面有几个页面，一块、两块、三块、四块、五块，就像浏览器页面一样：一个大浏览器，下面有好几个小子页显示出来。

每个点进去之后，都有一个进度表。如果是一个长期项目，就把它做成一个循环的进度图，是一个循环阶段，不停地转。谁在这里面做督导——这个活动应该有一个人做督导；谁在这里面做执行；有哪些成员在里面转。可以做得形象一点，就好像小朋友、卡通人物在上面转一样，头像在那条锁链上面转。

它相应的活动介绍，我觉得不需要另加文字来介绍。对它最好的介绍，就是介绍本身对它进行定位和分类。我们在框架上、形式上给它定位分类做好之后，它就不需要额外的介绍。额外的介绍可以很少，额外的文字性、文本性介绍，在我看来是框架设计者的无能。对于一个框架设计有能力的人，他通过这些类别的分类、这些架构的铺设，就可以实现自动介绍。

活动介绍可能只是有一些法律相关的声明，甚至法律相关的声明也可以做成模块化的。比如这个机构本身是什么，我们所帮助的是什么，我们自己是什么名义，这个机构是什么名义，这些款项走的是什么渠道，它的开支、核销都是怎样的。活动介绍本身，比如要有资料，那资料下面就来一句说明，活动介绍只要有一点点就行了。

这个开发工作量是有点大，因为要把这些框框都做出来。更不要说我们有一个长期计划，长期计划不仅仅是这么一个。其实可以就是一个纯 UI，在用户界面上把这些信息录入然后展示，其实是个体力活。

这些视频、图片，我们都会出视频来介绍。介绍里面的参与人员，你要另外弄成一个动态的。执行情况也都在它的流程表、流程图里面，后续回访也在它的流程表、流程图里面。我们要把人员通通都注册在这个网站里面。

虽然早期没有社群，但事实上里面的行动者都是它的组成部分。我们相当于一个显示界面，这个显示界面里面是有 agent 的，就像游戏里面的精灵，也就是游戏软件里能动的角色，我们叫行动者；参与做这件事情的人都会认领一个账号。这个东西甚至可以在给你权限的时候，让你自己去登记、自己负责，你就有权限自己来登记。核查你是不是干了这些活的人，由督导或者相当于监督者的人来核查，不需要我手动录入。

我们到时候做一个 APP，或者做一个客户端。你登上去之后，如果是行动者用户，你在这个项目里面就确定。或者我现场发个密码给你，你按照这个密码就能登进来，注册自己的活动，登记你今天干了哪些活。因为摊子铺大之后，我不可能面面俱到都去管，还专门找一个程序员一天到晚做这个事。我们要实现自动化。

制作是艰难的，但这个艰难的制作过程会让你后面不那么复杂，而且都是可实现的。它不仅仅是一个展示，更是一个很详实的数据库。这个数据库要实现自动化。我们现在有两个程序员，其中一个是做数据库的，所以希望他在这方面能帮帮忙，搭得好一点。

否则的话，就会导致每次……我始终强调，不用文本性来进行介绍。这样是为后面的社群构造铺路。这样行动者天然就是这里面有话语权重的人，有别人没有的标签，就是老资格、老革命。他早就已经在这个活动里面有各式各样的标签，他的话语权重不需要额外规定一票顶两票。他自己说话的时候自然有实践经验。至少在我看来，后面社群化肯定要接受监管。

我们不会立刻放开准入门槛，不会立刻让所有人都能注册，而是说你要参与行动，或者给予一定的支持。你可以作为支持者，sponsor，支持者也可以进来，在社群里面交流，sponsor 是可以的。包括这一次买勋章的，最后应当是我们都会发信息让你们录入，你可以在社群里面有一个账户。我们不会让所有人免费注册，你平时只能做一个观察员，连发言权都没有。

总结一下：这是一个大项目，要分成好多小项目，每一个子项目能够某种意义上实现动态化，让每个环节点进去有几张展示图，显示环节正在进行。上面会有用户目录，有用户信息，谁在执行这个环节，谁在监督这个环节，每一个都有这样的信息。当然，每个环节花了多少钱、减了多少，也有记录。然后我们背后是要做成 APP，用户可以在里面录入数据。行动者本人可以用 APP 来录数据，我服务器里面的数据库这部分向他的权限开放，他可以录进去，或者发送给管理员，由我把信息汇总后再更新。

徽章是一瞬间卖完的。所以到后面，买徽章或者买其他类似商品，相当于买了这个网站的一个登录权、一个参与权。我们希望把这个网站做得有层次一点、丰富一点。当然不是说不花钱在这里面就一点用都没有，而是说你可以帮我们。甚至这个网站我们到时候能开放一些，你帮我们做一些活动，充实里面的内容，那你也可以得到一些，相当于也可以赚钱。但这个钱你没办法提出来，这个钱就是我们的配捐。相当于我们是盈利者，我们做生意、有利润。但如果你在这个网站里面积累一定的贡献，你可以不花钱，在这里做一些文本工作、维护或者有效讨论，就可以得到配捐额度，你就有同样的钱，和其他花钱的人一样。

你把这些钱花在你要支持的项目，就点这里。你在自己的页面上点这里，我支持五十元。这五十元不是你出，是我们出；但事实上是你帮我们出，因为你那个劳动相当于从我这里挣到了钱，但这个钱我不会给你。这个钱你是义务劳动，我会把这个钱给到上面。举个例子，比如你帮我的视频做字幕，做完一个字幕挣了二十元，这二十元你就可以拿过来点支持他，二十元就配捐捐给他了。

就这样就好了。他的血条就会变长，你可以把他的血条变长，他的六千元预算就会变长。现在这个扩建项目有六千元预算。整个项目现在我们只有一万六千元预算，其中还有一万元我是要用在其他项目上的，比如志愿者来了路费报销，或者他自己里面的物资，以及长期的一些考虑。我们要考虑他哪些花费比较合理，还有哪些可以提高里面孩子晚托班的感受。

我们在这里是有额度的，有顶额，你每天就是接任务，每天有任务。你帮忙，比如把齐泽克的视频翻译成中文，你在翻译组里面。我们有齐泽克视频翻译组，也有劳动咨询组。这些组里面，你干的事情我不好给你钱，因为你是公益的，那我怎么办？我让你注册在这个网站的用户里面，你帮我们做这些事情，就可以拿到配捐配额，然后给他血条充血，相当于让他的血条变长。

二十年前的论坛实现不了这样的功能，现在这个功能可以实现了。所有这些活动最后都可以落实为你在我们社群里面的一个虚拟认定、一个勋章。我们就是把这个东西可视化，做成血条，做成动态化的。不同项目的进度上都有百分比，每个项目最好有一个百分比、一个数字。但那个数字也不要直接写成数字。能量化的，比如钱，可以写成数字；不能量化的，就做成进度条，已经读档读到这边了。这是第一个项目，将来肯定各地遍地开花，但我们不可能鞭长莫及，不可能亲自督导所有项目。

这个项目在苏州。如果铺开来做，和苏州很多公益团体都联系上、都做上的话，我人际关系好，本来就认识他们，所以草台班子已经搭起来，有的还不是很成熟。我们希望在这一个项目上，把这个网站以及我们这个团体、合作方、玩这个游戏的模式成熟起来。但这个扩建项目已经来不及了，肯定来不及；让所有人都注册到里面变成用户也来不及。不过后面常态运行是可以的。我们在扩建的时候就有数据了，说穿了就不会是假的、虚拟的；现在这些东西好多都是虚拟的。到时候有真实数据，用这些真实数据把框架做出来，把模型运行起来。框架长好之后，下一个项目直接往里面填就行。这样搞的话，这个网站，或者说这个互联网平台，在某种意义上蛮符合我的理想。它的行动性、现实性和及时性都比较强。

但我们不向不特定的公众开放这个论坛社群，所以一开始不会有论坛。论坛要接受监管、审查，我们没有那么大的人力成本去支持，要招审查员也招不起，现在都用爱发电了，所以不会有论坛。现在主要只是展示，但会有一定的交互。如果你是买进来的，就会有交互，你可以成为里面的用户，但这个用户不能随便发言，不过会有一定的发言权限，比如你可以对环节做出评价。有了评价就会有一些帖子，但这些帖子都是完全公开的，而且特别少，不会有特别专题化的讨论价值。所有言论、讨论都围绕项目本身，不会有废话。

目前就是这么个体量，我们会把项目进度、人员以及每个人的工作状况都反馈、做在这个里面。它第一步主要就是一个共识。用爱发电，你所有不都是用爱发电吗？一开始只能用爱发电，我给钱他们不愿意要，再说我又能给几个钱呢？这个设想不多，反而是程序员思维：你把它做好了，这个网站不需要很多人去打理。每一个网站使用者同时是内容的更新者，就不需要很多人打理。把权限架构搭好了，反而事半功倍、事一功万。

如果网站本身做得像个展示博客，那毫无用处，我干嘛要一个程序员给我做网站？我直接到网上买现成的网页制作软件，做个博客就行了，那没有意义。我做的是一个生态、一个宇宙，不是做一个网站、一个博客页面，不是只展示一张脸，这是很有深度和纵深的。

我们的长远是肯定要做成 APP 的，做成一个拳打豆瓣、脚踢知乎、头锤哔哩哔哩、屁股拱开微博微信的、很有用的 APP。我们要把它做成一个 APP。这是有鲜明价值取向和社会立场的一个 APP，而且严格实行注册准入制。你不买我的东西，或者说我不是强行一定要——到时候我们会有商品，是我们没有利润空间；我们到时候会出商品，是我们完全没有利润空间，你掏的钱全部到公益。这样做的前提是我们有募捐的名义。你不要说我现在卖东西还有利润率；我甚至说到那个时候，有没有物质本身的交换都取决于你。就相当于我卖卡片，这个卡片我给你转成虚拟卡，你要兑换成实体就给你寄过去；你不兑换成实体，就相当于你有一个兑换凭证一直放在那里，那这笔钱我一直就可以去做事情。这样的话既不浪费资料，也不浪费运费。以后有联谊模块，那是很后面的，我们暂时不会有联谊模块。但是你愿意在上面挂你的联系信息，那是你自己的事情；你愿意在上面挂你的联系方式，谁愿意和你交流就交流。或者说我可以让你有私讯功能，私人之间可以聊天，但这个数据量不能太大，可能就是简单的文字聊天。后期维护成本全靠这个，我跟你讲，钱全靠这个；这个网站肯定是要维护的，但这个钱全靠规模本身的扩大。视频反正就拍到这边了，二十几分钟，就是我们成员同事、技术同事自己去看一下、参考一下。这是我目前的一个意见：我对于外表这些东西不是太在乎，我在乎的是方向，设定一个方向；外表都是小问题，功能、结构性的功能有就行了。你这边弄个进度条，然后里面的人员和进度状态，点了这个进度条，这里展示的东西不一样，这样就有互动性了，其实是一个基本的互动性。
