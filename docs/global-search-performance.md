# 全站搜索的候选索引与性能验证

日期：2026-10-10。服务需要回找概念、原句和跨段关键词的复习者；对应产品原则中的内容查找、准确证据和静态独立前端。这里记录本地实现与验证，不表示已经部署。

## 实现

完整正文仍是最终搜索依据，默认综合搜索、正文原句、正文关键词、主题和排序规则均保持。构建从通过 SHA-256 校验的正文生成二字符到稿件的倒排表，按稳定哈希分为 64 个静态分区；不索引校验参照，不修改冻结正文。查询选取至多 8 个规范化 UTF-16 字符对，只下载涉及的分区并求稿件交集，再读取候选视频的现有正文分片。最后仍调用原 `searchEntries` 逐段精确验证，完成所有必要正文加载后才显示最终数量。

这是安全预筛选：字符对同时出现并不证明整词出现，误报交给正文匹配排除；跨段关键词按同稿件合并，元数据独占命中继续保留。manifest 与分区绑定同一正文指纹，版本错配、非法 postings、网络失败会显示搜索未完成并允许真正重试，不把加载失败当成零结果。候选分区与正文下载各限制 8 个并发；清空、换词和离开页面后停止排队，共享的已发出请求可完成缓存，不覆盖当前界面。

单字和其他无法用字符对缩小范围的查询直接使用原全量索引；候选超过类别稿件的 60% 时也采用完整索引，避免几百个正文请求。已加载完整索引会被后续查询复用。选择回退时可能已经下载候选分区，因此高频词不保证减少流量或耗时。页面空查询不下载候选、正文或完整搜索索引。局部视频查询继续只读取所选视频和类别的正文分片。

## 等价验证

`node scripts/check-search-equivalence.mjs` 对 583 篇实际稿件生成中段探针和边界查询，共 606 个查询，在三种方式和两种排序下完成 3,636 次深等价比较。比较完整稿件身份、类别、正文匹配、段落 ID、原显示文本、覆盖关键词、分数与排序。每次使用新的 loader，避免早期短词加载全库后掩盖候选路径错误。

额外单元覆盖中西文大小写、空白归一化、组合字符、emoji、跨段关键词、元数据独占命中、主题筛选、空结果、单字回退、缓存复用、非法版本和 postings、候选与正文失败重试、并发上限及过期队列。`node scripts/check-search-candidate-mutations.mjs` 确認等价断言能发现人为删除必需 posting 和将视频映射到错误正文的破坏。浏览器专项覆盖候选和正文各一次 503 重试、长等待后取消、晚响应、改词、IME、单字扫描，另复测类别、排序、分享、刷新和后退恢复。

## 性能条件

在 Windows Chromium 155、390×844、localhost 生产构建的 Pages 子路径上测量。先加载无查询首页，再启用 HTTP 缓存禁用与网络条件，之后从输入框查询“海德格尔”。正常网络和模拟 RTT 150ms / 125,000 bytes/s（1Mbps）各运行旧完整索引和候选方案 3 组冷、热查询，共 24 个样本。旧方案仅在测试浏览器中去除候选描述符，其他 UI、正文匹配和内容一致；正式实现保留完整扫描回退。

“输入到结果”包含 120ms 防抖、索引加载、精确匹配及 DOM 完成；不等于完成下一次屏幕绘制。热查询在同一页面清空后再次输入，使用内存缓存，HTTP 缓存依然禁用。统计所有新增候选 manifest、分区和正文请求，不只计算一个小索引。下表为三个样本的中位数：

| 条件 | 完整索引 | 候选方案 | 变化 |
| --- | ---: | ---: | ---: |
| 冷查询编码正文总字节 | 5,762,969 | 2,335,349 | -59.5% |
| 冷查询解码正文总字节 | 16,446,017 | 6,339,739 | -61.5% |
| 冷查询新增请求 | 1 | 125 | manifest 1、分区 3、视频正文 121 |
| 正常冷查询输入到结果 | 1,628.7ms | 709.6ms | -56.4% |
| 正常热查询输入到结果 | 157.9ms | 153.0ms | 0 新增请求 |
| 模拟限速冷查询输入到结果 | 47,690.3ms | 20,620.0ms | -56.8% |
| 模拟限速热查询输入到结果 | 183.3ms | 170.0ms | 0 新增请求 |
| 正常冷查询总解析时间 | 8.8ms | 13.5ms | 分区校验与多个 JSON 增加解析成本 |
| 正常冷查询总正文归一化 | 58.6ms | 27.0ms | 按候选正文派生 |
| 正常冷查询精确匹配 | 11.2ms | 5.0ms | 较少正文 |
| 正常冷查询 markup / DOM | 4.0 / 1.5ms | 2.0 / 1.4ms | 相同 131 篇结果 |

并发请求的下载 duration 可以重叠，不把它们的求和当成下载墙钟时间。候选确定额外花费约 4.3ms（正常冷查询）。CDP 强制 GC 后 JS heap usedSize 约从 29.63MB 降到 14.88MB；这是 Chromium JavaScript 堆指标，不是总进程内存，也不能保证其他浏览器相同比例。首屏资源不在上述搜索新增流量内；新分区 URL 描述符增加少量主脚本体积，候选内容本身仍按需加载。

另外五个查询的本地构建 gzip 字节求和为：海德格尔 2,335,349；胡塞尔 1,457,085；何为无意识 288,699；审美／痛苦关键词 928,198；单字“的”仍为完整索引 5,762,969。这个小样本不能代表所有查询；高频、短词或弱筛选可能回退，实际 CDN 协议、压缩、延迟和连接会改变端到端成本。

## 重测

生产 preview 启动后，用独立 Playwright session 打开正确子路径，再执行 `scripts/check-global-search-browser.js` 与 `scripts/measure-global-search-browser.js`。测量脚本输出完整的资源集合、编码/解码/传输字节、各阶段和 JS 堆样本。CLI 结果保存到 `.tmp/global-search-performance.log` 后，执行 `node scripts/summarize-search-performance.mjs` 导出 `.tmp/global-search-performance.json` 和 `.tmp/global-search-performance-summary.json`。这些机器测量文件位于忽略目录，不包含读者个人数据；可重复的脚本和本说明纳入仓库。
