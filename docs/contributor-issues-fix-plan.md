# 贡献者体验 Issues 评估与修复计划

## 范围与结论

2026-10-10（Asia/Hong_Kong）读取 GitHub 开放 issues，当前共 9 项：#64–#68 为通用来源契约切换，#70–#73 为本轮贡献者体验。本计划逐项评估后四项，并说明与前五项的交付关系；前五项的详细工作包仍见[通用契约计划](universal-contract-issues-plan.md)，不在此重新认定其所有上游实现细节。

四项均成立。#70 是跨视图定位缺陷；#71 是反馈流程能力缺口；#72 是参照页排版缺陷；#73 是现有正文索引之外的参照查找能力。建议保留 P1/P1/P2/P2。实施顺序由共享依赖决定，不等同于优先级排序：先准备参照派生结构和版本上下文，再打通 #70/#71，最后收口 #72/#73 的界面与任务验收。

服务校对贡献者及处理建议的维护者，改善“找到疑点 → 对照原文 → 回看来源 → 提交带准确版本的建议”。依据[产品哲学](product-philosophy.md)第 4.4、5、7、8 节，普通阅读仍是默认入口，核验工具按需出现；不引入账号服务、自动提交、在线改稿或审核流程，不改变独立静态前端边界。

本计划记录评估阶段。用户随后要求“开始修复”，已完成 #70–#73 的实现，详见[贡献者体验修复说明](contributor-experience-fixes.md)；下面的基线与工作包保留评估时的依据。合并、部署与 Issue 状态以 GitHub 的实际记录为准。

## 共享基础：参照结构与核对上下文

建议新增纯模块 `src/review-document.js`，在现有安全 Markdown token 管线上生成派生结构。以下名称是拟议设计，不表示已实现。

- 输入为已通过快照校验的当前参照 Markdown、稿件身份和 reviewArtifactSha256；输出技术块、段落组、原文/AI 整理稿/疑点、来源节点及原有块 ID。
- 检查明确可支持的 token 形状，不用对渲染后 HTML 做大范围正则替换，不把正文里的“原文：”自动当作新结构。未来新来源格式须以实际 producer fixture 确认，不能凭本机较旧上游模板认定 universal-v3 的最终参照形状。
- 保留全部 token、未识别段落及“未匹配的参考字幕”等尾部区段。结构不完整时显示通用原稿，查找和复制仍可用，语义分组和自动映射则明确降级。
- 保留 prepareDocument 已生成的原块 ID，并保持既有标题锚点可解析；新增 group ID 必须独立命名。排版分组不能改变正文索引编号，也不能让历史链接跳到另一个字段。
- 仍使用 html:false、链接安全规则和文本转义。回看 URL 复用快照已提供的来源；平台/视频/分段或时间无法确认时显示原链接，不生成猜测的时间戳。
- 原始完整 Markdown 下载/复制与原稿视图可达；“AI 整理稿”明确是 AI 基线，当前正文可能经过后续编辑。当前稿件状态不等于对参照作了人工审核。

核对上下文应统一包含：manuscriptType、editionId、正文 contentSha256/artifactSha256、aiRevisionId、reviewArtifactSha256，公开稿另有 releaseId；文档模式、块 ID、段内偏移、选句及邻近上下文。来源信息从有效来源模块读取，不自行推断。

## 实施顺序与门禁

### 1. 确定结构识别并先收敛参照排版（#72 基础）

用当前合法样例、人工编辑后正文和目标新契约的真实 fixture 固定 parser 行为。以原有 ID 为基础生成段落组，将技术字段放入默认折叠详情，来源编号与回看操作分开。主标题使用准确稿件标题并单独标记参照模式；原参照标题在原稿/详情保留，不能任意截断不同标题的后缀。

首轮采用分组的上下对照，不默认展开所有长原文，不新增多层卡片。桌面并排属于可选优化，需验证中英文长段落的可读性。原文需要可查、可展开，查找命中落入折叠区域时须先展开后定位。

门禁：所有可识别和不可识别信息均可访问，旧锚点、原始复制和安全渲染保持有效；不会因未知格式漏掉疑点或来源。

### 2. 打通正文与参照的往返（#70）

优先捕获正文中的有效选句；没有选句时使用当前可见正文块，并剔除元数据/页脚/工具内容。引用完整版本元组，保存单篇或连续阅读当前 edition 与原位置。

匹配规则先采用 Markdown 解码后的纯文本和统一空白的唯一精确匹配，目标限定为参照的 AI 整理稿；选句可作唯一连续片段匹配。不能忽略标点、模糊相似或按段落序号自动认定对应；多结果显示候选，零结果显示无法对应并保留原句供手动查找。匹配成功也只表明文本对应，不等于学术或审核认证。

往返位置保存于同一浏览会话和 history.state，区分每个文档模式。浏览器 Back、正文页签返回、连续阅读返回分别验证。DOM 节点在重渲染后会失效，[reader-tools.js](../src/reader-tools.js) 的现有节点引用恢复不能直接用于跨页；应保存可序列化锚点与比例，版本校验后重新查找节点。

优先级规则：显式有效分享锚点 → 浏览器该页面历史位置 → 本次核对定位 → 用户主动选择本地继续阅读；布局异步完成后复位须沿用“用户已接管则停止”的行为，不能不断拉回。普通未带核对上下文的参照链接仍从头打开。

门禁：唯一匹配正确定位；重复、编辑拆合、无对应与旧版本均不误跳；review 不写入正文进度；连续阅读不切换到错误分 P。分享上下文只含有界字段且绑定版本，不将完整长句强塞 URL。

### 3. 提供参照本地查找（#73）

review 固定工具改为清楚的“参照查找”，视频正文查找保留为另一明确入口。通用 parser 回退时搜索当前完整原稿；支持结构时显示原文/AI 整理稿/疑点范围，不混入元数据命中冒充原文。

复用既有安全文本匹配与高亮基础，但参照结果独立于全站目录及视频正文导航。先交付单查询的本地文字查找、命中总数、上一处/下一处、无结果、清空/退出与返回核对处；不把全站关键词跨段规则未经说明套到参照内。输入法组合期间保留输入节点，避免高亮/折叠导致定位偏移。

门禁：原文独有、整理稿独有、疑点独有、重复词和中英文均正确；折叠内容可定位，退出恢复焦点与核对位置，不新增索引网络请求。未知参照结构时提示范围为原稿，不能宣称已经识别了字段。

### 4. 完成站内建议整理与交付（#71）

建立纯反馈文本生成模块与浏览器表单模块，buildIssueUrl 使用统一生成结果，避免预填和复制内容不一致。

- 正文和参照的主操作行及中段工具提供入口；手机可用“纠错”触发面板，避免给每段增加永久工具栏。进入面板前保存 Selection 范围，失焦后仍能带入原句。
- 仅接受当前可访问正文/参照内容区域内的选择；跨段保留所属块及上下文，跨工具/跨篇选择提示缩小范围。没有选句时明确允许手填，不假造段落证据。
- 对话框表单包含原句、上下文、建议和理由，版本/来源信息只读展示。处理焦点进入、Escape、关闭后返回触发点、未完成内容保留；“复制全文稿件”仍独立存在。
- 反馈草稿采用独立 sessionStorage key，按准确文档版本和模式隔离，仅保存当前浏览器会话，定义数量/长度上限和清除入口；存储失败保持当前内存输入并提示，未知格式不覆盖，旧版本草稿可复制但不能自动改绑新版。它不迁移旧阅读历史，不承诺跨设备或浏览器关闭后保留。
- 复制完整反馈后显示“已复制，尚未提交”；失败提供可选中文本。跳转说明 GitHub 登录要求，本地站点不能确认用户是否在 GitHub 完成提交。
- 给 GitHub 预填 URL 定义应用级长度限制并测试百分号编码后的长度；该阈值不是 GitHub 保证。超限保留完整文本并提供复制 + 简短来源身份链接，不静默丢掉建议内容，不自动发送或创建 Issue。

门禁：选句与手填均能形成可复核建议；正文/参照/公开/草稿身份准确；无登录、剪贴板失败、sessionStorage 失败、跳转取消与版本变化均有明确反馈。返回阅读不覆盖正文位置。

## 与 #64–#68 的实施关系

P0 的 universal-v3 切换仍优先于这轮体验优化。新 parser、文字匹配和反馈 formatter 可先设计与验证，避免在尚未完成来源模块时新增 bvid/pageIndex 依赖。不能为赶本轮修复放宽构建校验或导入私有 review.json。

建议在 #64/#65 的准确版本和来源接口确定后，在同一集成分支接入本轮 UI；#66 保证工具不覆盖进度，#67 提供反馈/回看所需来源事实。#68 使用真实新格式双快照进行最终交付验证。当前 v2 数据仅作本次诊断基线，不承担新接口的合法验收。

本轮体验不是 #68 切换契约的额外阻塞条件。若契约升级先完成，先交付已验收的 #64–#68，本轮可随后以完整通过测试的独立 PR 发布；不能把 #70–#73 尚未完成作为长期阻止 P0 的理由。若本轮先准备好，则应接到目标新格式，不增加双轨来源或旧格式迁移。

## 验证矩阵与完成标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 文档派生 | 已知结构、未知模板、残缺字段、额外尾段、转义 Markdown、危险链接、长 hash；无信息丢失，完整原稿与 bytes 保持不变 |
| 版本与映射 | 一致正文、人工改词、拆段、合段、重复原句、缺失参照、换 edition/文件 hash；唯一精确匹配才自动定位，错误身份拒绝复用 |
| 路由与位置 | 全站命中/视频命中/直接打开、页签切换、前进后退、连续模式、打开新标签页；位置、查询来源、当前篇与显式锚点准确 |
| 参照查找 | 仅原文、仅整理稿、仅疑点、多处、无结果、中英文、输入法、折叠字段、清空/退出；显示正确范围且没有全库请求 |
| 反馈 | 文本选择/跨段/未选择/跨篇选择、草稿与公开、review hash、长 URL、未登录、复制/存储失败；完整建议可得，未提交状态准确 |
| 可用性 | 320×640、390×844、1440×900、深浅主题、文字放大、键盘、减少动态效果；对话框焦点、触控、无横向溢出、回看不拆字 |
| 正文保护 | review 和临时工具不覆盖正文记录；返回目录仍保留查找条件；连续阅读按实际来源顺序不串版本 |

实施时增加独立的 parser/唯一匹配/反馈身份与长度边界纯函数测试，以及一条浏览器任务脚本覆盖“搜索命中 → 参照 → 回看链接检查 → 整理建议 → 复制 → 返回阅读”。可接入现有 scripts/check-reader-browser.js 与进度检查的环境；浏览器测试不向 GitHub 真正发布测试建议。

交互验证需记录控制台错误、相关网络请求、位置恢复和修改前后首段可达性。同一固定样例在手机应让首个核对段落标题进入 844px 首屏，桌面进入 900px 首屏；超长实际内容同时记录可读行数与改善幅度，不为达到像素目标隐藏准确标题、状态或降低触控尺寸。

最终对待发布 commit 执行 pnpm test、pnpm validate、Pages 子路径构建与上述浏览器矩阵；确认两份冻结快照文件及 manifest 没有被视图加工改写。功能交付后再更新 README 与产品哲学的“已实现能力”说明。本计划通过文档检查不等于功能验收通过，也不等于站点已部署。
