# 内容发现交付说明

依据 [项目哲学](product-philosophy.md)，本次改善复习者凭原句或术语找回上下文，以及学习者查看同视频已收录分 P 的任务。对应 [下一阶段计划](next-reading-features.md) 的前三步；连续阅读模式仍待实施。

## 已实现

- 视频总览：目录的视频标题进入稳定的 `?video=<BVID>&view=all` 入口，单篇链接仍直达正文。总览按实际 P 编号展示文章，保留同分 P 的发布版与公开预览，并可切换稿件类别。
- 收录说明：展示分 P 与稿件数量、原视频、源视频标签、分版本类别的阅读时间估计。前部未收录和内部编号间隔明确提示，不推断末尾是否缺失，不声称完整收录。
- 综合搜索：匹配标题、摘要、来源标签与正文，正文证据优先；标题命中不会遮蔽同篇正文命中。
- 正文原句：在可读正文段落内连续匹配，忽略首尾及连续空白，大小写不敏感；保留标点区别，不跨段落拼接原句。
- 正文关键词：用空白分隔，去重后所有词必须在同篇正文出现，允许跨段落。标题和标签不能代替正文满足条件；不自动混入只命中部分词的文章。
- 多个命中：显示命中段落数量，先展示两个片段，可展开其余命中；每个片段都有具体稿件和段落链接，并在正文高亮该段命中的词。长段落分散的关键词分别提供上下文。
- 可解释排序：正文结果优先；多关键词中同段覆盖越完整越靠前，同分保持原目录顺序。按视频聚合时以最高相关分 P 决定视频位置，组内仍按 P 编号及稿件类别排序。
- 视频内搜索：复用三种查找方式，仅搜索当前 BVID、当前稿件类别。搜索后切换类别保留词语和方式，正文及校验参照页提供返回总览入口。
- 查询恢复：URL 包含 `view`、`video`、`q`、`mode` 和全站搜索的 `tag`，参数严格校验并拒绝与稿件路由混用；标签必须来自当前快照的源标签，视频内查询不混用全站标签。共享 URL 可在新页面恢复查询；会话与历史额外保留结果展开状态和滚动位置。不同视频与类别的会话状态分别保存。

## 内容与技术边界

保持独立静态前端，未增加依赖或运行时后端。总览使用已有元数据与派生摘录，不主动加载 Markdown 或全文索引；输入查询后才加载按发布类别拆分的索引，进入正文才请求对应稿件。AI 校验参照不进入正文搜索索引。

未改写 `content/`、`draft-content/` 的正文或 catalog。视频标题来自收录稿件的冻结标题；源标签保留原值。正文摘录不冒充编辑摘要，查询命中不代表文章事实正确。

这是可解释的字面文本检索，不支持同义改写或语义问答。首次搜索仍需加载所选类别的完整正文索引；索引分片和 Worker 可依据更大规模的测量结果评估。共享链接恢复查询条件，结果会随部署快照变化；片段仍绑定具体稿件版本。

## 验证与复测

运行 `pnpm test` 与 `pnpm build`。合成数据覆盖跨段落关键词、元数据与正文冲突、原句空白与标点、高亮安全、同分 P 多版本、数字排序、缺失范围、URL 往返及非法参数。

浏览器脚本使用已安装的 Playwright CLI：

```powershell
pnpm dev
playwright-cli -s=p0 open http://127.0.0.1:5173/
playwright-cli -s=p0 run-code --filename=scripts/check-discovery-browser.js
playwright-cli -s=p0 run-code --filename=scripts/check-reader-browser.js
playwright-cli -s=p0 run-code --filename=scripts/check-reader-errors.js
```

新增脚本验证真实 13 分 P 总览、按需请求、跨段落证据、单个命中定位、校验参照返回、展开项与查询恢复、新标签页共享查询、空发布类别、历史导航、无结果、原句、375/768/1024/1440 宽度、手机深浅主题、全站反查和中文输入。截图存入忽略的 `artifacts/`。

子路径生产复测：以 `pnpm build --base=/markdown-reading-site/` 构建并在相同子路径的 Vite preview 页面运行以上脚本。浏览器示例依赖当前真实内容，内容变化后需调整示例；单元测试使用独立合成内容。

本次交付验证：42 项 Node 测试通过，快照校验与 Pages 子路径构建通过；新增任务脚本、原阅读流程及加载失败/重试脚本均通过。反转“全部关键词须命中”条件后测试失败，恢复代码后通过。同步已合并的内容导入后，再次对 320 篇快照完成上述验证。开发机检索计算约 37–39 毫秒，结果标记生成约 3–7 毫秒；这不包含网络、DOM 布局或真实手机耗时，不作为性能保证。该快照的正文索引约 7.8 MB（构建 gzip 估算约 2.7 MB），目录与摘要 chunk 约 503 kB，构建有体积提醒；索引分片仍待后续优化。
