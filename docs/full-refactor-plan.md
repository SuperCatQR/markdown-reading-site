# 阅读站全量重构计划

状态：第一版接线后的 A01–A25 验收问题已修复；当前任务回归与资源证据见 [验收修复交付](site-acceptance-fixes-20261011.md)。旧未接线模块的 G 阶段物理删除仍单独保留，不将历史测试数作为新页面完成证据。2026-10-11 根据维护者“完全重构、解耦模块、不考虑兼容性”的要求制定；旧路由不保留兼容层，最终以本文件的验收门槛为准。

当前交付范围：`src/main-refactor.js` 启动新的资料库、搜索、最近阅读、阅读和核验页面；`packages/content-core` 提供构建与浏览器共用的 Markdown、来源身份、版本、搜索候选和校验参照模型；`src/refactor/services` 管理内容、搜索和本地状态；`src/refactor/core/router.js` 是唯一的新 hash 路由入口。旧实现仍作为历史测试与未接线模块保留，生产入口不再加载它们，待整体验收完成后按第 G 阶段删除。

## 1. 目标与决策

重建导航目录、搜索、阅读、核验和反馈的页面组织，同时重建构建数据管线、模块依赖、状态所有权和样式体系。交付一个替代现有前端的新实现，最终删除旧实现，不维护两套界面或双路由。

服务对象及可观察结果：

| 用户 | 任务 | 新实现应达到的结果 |
| --- | --- | --- |
| 首次访问的文字读者 | 了解内容并打开一讲 | 首屏出现可读条目，搜索与内容是视觉主体 |
| 看过视频的复习者 | 找回概念或原句 | 快速比较不同视频的短证据，直接进入准确命中段落 |
| 持续学习者 | 阅读多个 P、中断后继续 | 同一阅读器承载单篇与连续阅读，恢复当前准确版本的位置 |
| 查证者与校对贡献者 | 回看来源、核验并反馈 | 工具按需加载，保留原句、来源与完整版本身份 |

依据 [产品哲学](product-philosophy.md) 的内容优先、查找与连续阅读、辅助信息逐层展开、来源与版本准确原则。产品继续采用独立静态前端、构建时验证公开快照、浏览器本地个人状态；账号、运行时后端和跨设备同步不进入本轮。

技术基线采用现有 Vite、原生 ES modules、markdown-it 和 CSS。接口通过 JSDoc 类型和明确的数据结构约束；本轮优先解决责任与依赖。任何后续语言或框架变化应独立说明收益，不成为解耦成立的前提。

## 2. “不考虑兼容性”的执行范围

| 对象 | 决策 |
| --- | --- |
| 旧查询路由、hash、段落地址 | 删除旧解析器与重定向，新地址使用唯一新路由格式 |
| 旧 localStorage / sessionStorage / history.state | 不读取、不迁移；新命名空间从空状态开始，不执行全域 clear |
| 旧组件、CSS 类、data 属性、DOM 自定义事件 | 无保留要求；最终删除旧绑定与样式 |
| 旧模块导出与内部函数签名 | 按新边界重写调用方，不保留兼容导出 |
| 构建派生索引与前端资产清单 | 定义单一新版本，完整重新生成，不维护旧消费者 |
| 旧测试中的选择器和 HTML 字符串断言 | 替换为新行为与接口测试；不为通过旧测试保留旧结构 |
| 上游当前公开快照 | 继续严格消费 README 的 universal-origin-v1，构建适配层负责验证与映射 |
| 冻结正文、来源、审核/发布状态、版本证据 | 准确读取和保留；真实历史来源仍如实展示 |

当前有效快照是本次重构的数据输入。上游导出协议如需改变，另立上下游协同任务；本计划由新的构建适配层严格读取当前合法快照，不增加旧格式兼容或放宽内容证据。

新前端上线后，旧分享链接和旧浏览器进度不再恢复；这是本计划明确接受的结果。部署切换与必要回滚以整份有效站点为单位，回滚不引入新旧混合运行。

## 3. 证据与主要成因

本地审查确认：目录把介绍、数量、筛选、搜索选项与最近阅读堆在结果前；“主题”主导航只打开筛选弹层；搜索时取消视频组折叠，首组全部命中 P 铺开。390 × 844 干净会话搜索“主义”时，首结果顶部 467px、首视频组 5579px；有最近阅读时，首结果顶部为 635px。

当前本地双快照为 1024 个视频、1228 篇未发布、0 篇已发布；源标签与编辑摘要均为空。数据统计与界面测量仅说明本地现状，实施时需要重新测量。

结构成因：

- src/main.js 集中路由、目录、查询、阅读初始化、工具生命周期与滚动恢复。
- 普通正文渲染前必须加载 contributor-browser.js，辅助工具成为阅读前置依赖。
- scripts/reader-content.js 从 src 导入来源身份、正文处理与稿件函数，构建管线依赖前端目录。
- 阅读工具通过全局 DOM 事件协调保存、暂停、恢复，多处模块可修改同一状态。
- 单篇与连续阅读各自拼装页面，连续阅读加载 P 时重画整体界面。
- 七份 CSS 依次加载，同一组件样式分散覆盖。

## 4. 新页面组织

### 4.1 顶级页面与导航

常驻全站导航只提供“资料库”和“最近阅读”；搜索由明显的输入入口进入。阅读和核验采用适合各自任务的页面壳，保留明确返回目标。

| 页面 | 唯一主要职责 | 次要功能 |
| --- | --- | --- |
| 资料库 | 浏览视频并打开正文 | 精简范围筛选、短继续阅读入口 |
| 搜索 | 比较相关视频和命中证据 | 查找方式、发布范围、排序、逐组展开 |
| 最近阅读 | 恢复或管理本地阅读记录 | 失效说明、删除与清空 |
| 阅读 | 阅读当前 P、前后切换或连续阅读 | 当前视频目录、本文导览、视频内查找、排版 |
| 核验 | 查看当前准确版本关联的校验参照 | 参照查找、来源证据、发起反馈 |

来源与版本作为阅读/核验的按需面板；反馈作为独立延迟加载工具。没有额外视频总览中转页。资料库标题直接进入该视频首个可读稿件；搜索结果直接进入所选命中。

主题属于内容发现能力，在有实际索引时进入资料库的发现区域。没有数据时不显示可操作的主题筛选，不提示用户反复改词。现有 [自动主题提案](automatic-topics-design.md) 继续作为独立提案：不在本轮默认为已批准算法，不把推导主题写入冻结来源标签。以后启用时提供来源类别与证据，并同步修改产品原则和 README。

### 4.2 资料库

结构固定为：简短说明 → 搜索入口与一处范围筛选 → 轻量继续阅读（有记录才显示）→ 一处数量说明 → 视频列表。

- 单 P、多 P 使用相同的视频行结构：完整原标题为主链接，P 数量、真实状态、时长为次要信息，来源操作放在次级位置。
- 单 P 不增加独立的重复“阅读正文”行；多 P 可以展开选择 P，聚合状态按实际分布表达，逐篇状态在展开后可见。
- 默认每批 20 个视频；展开状态与返回位置由目录会话负责。
- 标题可在列表中折行或展开完整文本，原始标题不改写；没有编辑摘要时不拿首段充当摘要。
- 默认按完整标题稳定排序；若提供来源时间排序，仅使用已知来源时间，未知时间明确置后，不使用导入/编辑时间伪装来源时间。
- 继续阅读压缩为标题、P、继续操作，管理功能只在最近阅读页提供。

### 4.3 搜索

独立搜索页省去资料库宣传标题、全库介绍和最近阅读模块。结构为：查询输入 → 紧凑的筛选/方式/排序区 → 命中数量 → 视频结果组。

- 每组默认最多 2 个命中 P，每个 P 默认一段短证据；其余 P 与证据主动展开。
- 首组不因命中 P 多而占据数个屏幕。完整命中保留在结果模型中，呈现层只控制默认展开规模。
- 综合、连续原句、全部关键词的搜索语义分别定义；连续原句和全部关键词必须有正文证据，不用元数据放宽准入。
- 搜索结果排序与连续阅读顺序是不同字段：预览可选最相关 P，展开目录与阅读顺序保持真实 P 顺序。
- 查询、范围、方式和排序可以分享；列表展开和滚动属于当前会话。
- 查询变更取消旧任务；旧响应不得覆盖新结果。索引失败有局部重试，不销毁查询。
- 搜索页与视频内查找调用同一个 SearchService，差异由显式 scope 表达。

### 4.4 阅读与核验

- 一个 ReaderSession 和正文组件承载单篇/连续阅读；模式只影响加载策略，不再维护两套页面生成逻辑。
- 单 P 隐藏同视频目录。多 P 在桌面使用一个可收起侧栏，在窄屏使用一个目录抽屉，避免两份相同目录同时可操作。
- “目录”内区分“同视频分 P”和“本文导览”。正文缺少小标题时，导览只按原文块与摘录定位，不生成虚构章节。
- 常驻头部突出返回、当前位置、目录、查找、更多；连续阅读与排版在适当位置开启，来源、核验、反馈按需展开。
- 来源状态在正文头部用紧凑形式准确表达，详细来源、迁移归属及版本证据在来源面板保留。
- 连续阅读显式加载下一 P，增量追加正文；加载失败时已读内容和当前位置保留。读回已加载 P 时更新当前版本、进度及可分享位置。
- 连续队列按视频与稿件类别组织，不因为搜索范围为“全部”就混入同 P 的两个版本。
- 核验是独立页面，采用中文字段、易读时间与证据层级；原始参照可访问、复制，原始内容及哈希不变。
- 从正文去核验再返回使用显式 ReadingLocation；不依靠旧 DOM 还存在。直接分享的核验页不会假装存在前序阅读会话。

## 5. 模块依赖与目录

```text
packages/
  content-core/          来源身份、准确版本、正文块、搜索语义等纯逻辑
build/
  snapshots/             Node 文件读取、当前快照验证、原始输入适配
  projections/           目录、详情、搜索及可选发现索引生成
  assets/                内容指纹、资产清单、构建输出
  vite/                  开发服务器与 Vite 插件薄适配
src/
  app/                   入口、路由编解码、依赖组装、页面生命周期
  platform/              fetch、storage、history、剪贴板和浏览器观察器适配
  services/              内容仓库、搜索服务、进度仓库、偏好及反馈服务
  features/
    library/             目录会话与页面
    search/              搜索会话与页面
    recent/              阅读记录页面
    reader/              阅读会话、定位协调、正文与目录
    verification/        核验会话与参照页面
    feedback/            建议编辑器与提交入口
  ui/                    无业务数据访问的按钮、菜单、抽屉、对话框等
  styles/                token、基础样式、排版与壳布局
test/
  core/                  纯逻辑与契约
  services/              用假资源/存储验证异步、失败及取消
  browser/               真实页面任务、布局与可访问性
  fixtures/              验证有效的最小快照和边界样本
```

依赖规则：

1. content-core 不依赖 DOM、Node 文件系统、页面或浏览器存储；构建与运行时共用它。
2. build 只依赖 content-core 和 Node/构建工具，不得导入 src。
3. platform 只封装浏览器机制，不知道“连续阅读”“校验参照”等业务。
4. services 使用注入的 platform 能力及 content-core，不能导入 features、ui、app。
5. features 使用注入的服务接口、content-core 和 ui；不能直接调用 storage/fetch/history，也不互相导入实现。
6. 跨功能切换以类型明确的导航意图交给 app；阅读位置由 reader 的公开接口交付，核验与反馈不查询 reader 的私有 DOM。
7. ui 不获取稿件、不搜索、不保存阅读状态；业务信息由调用方提供。
8. app 是唯一的依赖组装与跨页面导航位置，入口只启动应用；不拼页面正文或执行搜索算法。
9. 依赖检查覆盖静态与动态导入，CI 拒绝环形依赖、跨层反向引用及越过功能公开入口的深层导入。

以真实职责建立模块，不为每个函数增加接口。服务只暴露当前需要的能力，不引入全局消息总线或通用插件框架。

## 6. 关键数据接口

| 模型/接口 | 内容与责任 |
| --- | --- |
| SourceRef | platform、externalVideoId、partIndex；平台身份保留大小写 |
| VersionRef | 稿件类别、edition、AI revision、content/artifact/review 哈希；发布稿另含 release；完整冻结身份不从目录投影重算 |
| ArticleSummary / VideoSummary | 列表需要的标题、实际状态、P、时长与详情引用，不预载全部来源和核验文本 |
| ReadingLocation | VersionRef、documentModelVersion、blockId、段内相对位置；有足够身份判断位置失效 |
| SearchRequest | query、mode、sort、scope；scope 显式包含类别及可选视频身份 |
| SearchResultGroup | 视频身份、排序依据、匹配 P、完整命中块及短证据；默认展开数由视图决定 |
| ContentRepository | 读取目录、详情、正文、参照；按准确内容指纹缓存，失败可重试 |
| SearchService | 接收 SearchRequest 与 AbortSignal，加载需要的分片并返回完整结果模型，不返回 HTML |
| ProgressRepository | 保存、读取、删除及核对准确版本，返回可用/失效/不可保存状态，不滚动页面 |
| FeedbackService | 将原句、建议和 VersionRef 组合为反馈文本/Issue 链接，不控制阅读页面 |

所有异步读取显式接收 AbortSignal。底层缓存不得让一个调用者的取消错误终止其他活跃调用者；失效/失败 Promise 不永久缓存。缓存按大小或使用范围设限，避免连续阅读无限积累正文、DOM 与参照。

正文解析、块编号、搜索文本提取共用 content-core 的文档模型，构建索引与运行时正文使用同一 documentModelVersion。单篇和连续阅读复用相同块身份，不通过切换模式改写段落 ID。完整定位使用 editionId + blockId，跨 P 无冲突。

## 7. 状态所有权与生命周期

| 状态 | 唯一所有者 | 持久化与恢复 |
| --- | --- | --- |
| 当前页面及可分享条件 | Router | URL，统一 parse/serialize，非法值明确失败 |
| 当前浏览历史条目的滚动/返回上下文 | NavigationSession | history.state + 有限会话存储，只表示真实前序页面 |
| 目录展开、已显示数量 | LibrarySession | 当前会话，离开前保存 |
| 搜索任务、结果展开、索引加载 | SearchSession | URL 保存查询，会话保存展开与滚动 |
| 阅读模式、已加载 P、当前 P | ReaderSession | URL 保存模式及当前准确篇目，会话保存流 |
| 正文块、段内位置及恢复优先级 | ReadingPositionCoordinator | 显式链接优先、浏览历史其次、用户选择的本地恢复再次 |
| 当前工具、焦点及打开前的位置 | reader 内的 ToolController | 临时状态，关闭按明确意图恢复或保留新位置 |
| 阅读进度 | ProgressRepository | 新 localStorage 命名空间，只处理新格式 |
| 主题/阅读排版偏好 | PreferencesRepository | 新 localStorage 命名空间，失败不阻止当前排版 |
| 反馈草稿 | FeedbackSession | sessionStorage，按准确版本与正文/参照分别保存 |

挂载页面使用 mount({ root, services, navigation, signal })，返回 dispose()。页面切换由 app 先取消旧挂载再释放订阅、观察器和 DOM 监听；旧异步结果不能提交到新页面。挂载失败展示该页面的错误状态并释放已创建资源。

服务与会话返回数据或显式状态变化；页面只在自身 root 内绑定事件。取消当前 document 级点击转发和跨模块 reading-tool-* DOM 事件；系统级 popstate、主题媒体监听由 app/platform 各自单点管理。

工具打开、关闭、调整排版、正文增量加载都通过一个位置协调器保存/恢复语义块位置。用户主动滚动正文或选择命中会转移控制权，不能在工具关闭或迟到响应后倒退用户的新阅读位置。

## 8. 新路由与数据加载

静态托管采用 hash 路由，刷新深链不要求服务器重写，也不需要旧参数兼容层：

```text
#/library
#/search?q=概念&mode=general&scope=all&sort=relevance
#/recent
#/read/<editionId>
#/read/<editionId>?flow=continuous&block=<blockId>
#/verify/<editionId>?block=<referenceBlockId>
```

以上位于实际托管 base path 之后，根路径进入 #/library。同一 Router 负责编码和解码；hash 已作为路由使用，块定位放在 query 中。搜索到正文的高亮条件按 SearchRequest 的新白名单编码，反馈和复制链接只调用该 Router。

路由使用 edition 精确定位，同 P 的不同版本不静默互换；来源中出现真实 preserved-legacy-body 等归属仍按数据如实表达。旧链接不识别时显示清楚的未找到页面。

加载边界：

1. 首屏只加载应用壳、最小资产清单及目录投影；不将全部 origins、完整核验身份和 Markdown URL 映射打进入口。
2. 构建层严格验证快照，再生成带双 snapshotId 的单一版本资产清单。清单通过内容指纹绑定目录、详情、正文、参照与索引。
3. 阅读只取当前篇正文和所需详情；同视频目录来自轻量目录模型。
4. 来源、核验及反馈按需加载；工具代码或参照请求失败不得阻止已取得正文阅读。
5. 全站搜索保留候选缩小与视频分片的能力；宽泛查询可使用完整索引。视频内搜索不得退化为加载全库。
6. 对完整索引和分片执行等价性测试，索引不能修改搜索准入及精确定位语义。
7. 详情与正文缓存键按准确版本/文件哈希区分。进度有效性按该文档版本判断，不能因为其他文章导致全站 snapshotId 改变就清空全部进度。

## 9. 样式与交互约束

- 保持“安静、有秩序的资料室”方向，采用统一中文排版、间距、色彩、边框与层级 token。
- 样式按所有权组织：全局 reset/token/正文排版/页面壳；功能样式与功能同目录；公共控件样式与 ui 同目录。
- 不再创建按修复轮次命名的 experience/followup 样式；同一个组件的布局与断点规则由一个文件负责。
- 功能选择器限定根范围；约定层叠层，禁止在不相关功能中覆盖 reader-header 等组件内部规则。
- 桌面与手机使用同一业务模型，布局按容纳能力切换，不复制独立状态机。
- 触控目标至少 44 × 44px，320px 宽可用；键盘焦点、Escape、抽屉焦点返回、减少动态效果纳入页面验收。

首版量化设计目标（实施后验证，不声称现已达到）：

| 场景 | 目标 |
| --- | --- |
| 390 × 844 资料库，含一条最近阅读 | 首个可读视频标题顶部不超过 300px |
| 390 × 844 搜索“主义” | 首个结果标题顶部不超过 240px，默认首组高度不超过 520px |
| 默认搜索展开 | 每视频最多 2 个 P，每 P 一段短证据 |
| 390 × 844 / 320 × 768 阅读 | 常驻头部不超过 72px；长标题正文起点目标不超过 280px |
| 单 P 阅读 | 无同视频目录侧栏，无无效目录切换入口 |
| 任何工具失败 | 已加载正文可继续阅读，位置和进度状态可判断 |

超长标题保留完整文本访问方式；尺寸目标通过层级收敛达到，不依靠删除必要状态、缩小触控区域或伪造摘要。

## 10. 实施阶段与交付门槛

按依赖顺序开发；允许分阶段提交，最终一次切换到新站。过渡期间的新旧目录只是开发组织，不能进入最终交付的双栈。

| 阶段 | 工作与产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：锁定体验与契约 | 目录/搜索/阅读/核验的桌面手机结构稿；确认新路由、模型和验收样本 | 页面任务与数据接口完整，空标签/摘要及空发布范围有明确表现 |
| B：纯模型与构建管线 | 建立 content-core；迁移严格快照验证；生成新目录、详情、资产和搜索投影 | 构建不导入 src，哈希及真实状态验证通过，派生产物可重复 |
| C：应用壳与服务 | Router、挂载销毁、内容仓库、搜索服务、进度/偏好仓库 | 边界检查与服务失败/取消/竞争测试通过，旧 URL/存储无依赖 |
| D：资料库与搜索 | 新顶栏、统一视频行、独立搜索页、有限默认命中、最近阅读页 | 首屏指标通过；查询、展开、返回、重试与键盘操作完成任务 |
| E：统一阅读器 | ReaderSession、单篇/连续策略、目录、导览、查找、位置协调 | 连续追加不重建页面；模式切换与回滚 P 位置准确，单 P 无冗余目录 |
| F：来源、核验与反馈 | 延迟加载来源/参照/建议编辑器；准确版本及原句关联 | 断开工具请求正文仍可读；核验返回位置准确，反馈字段完整 |
| G：切换与删除 | 切换入口，删除旧 src 模块/七份 CSS/旧索引插件/旧浏览器脚本，更新 README 和产品文档 | 只有新路由、新状态、新样式和新构建数据消费方式，无兼容导出 |
| H：整体验收 | 内容校验、测试、构建、生产预览、子路径部署和真实任务回归 | 所有阻断项关闭，产出可审阅变更、验证记录与明确切换影响 |

在 B 阶段为构建共享逻辑建立稳定入口，在 C 阶段让浏览器能力可替换；D/E/F 只组合这些接口。遇到新需求先判断数据/服务/会话/视图的归属，禁止重新塞回入口文件。

## 11. 测试重建

保留当前快照真实性、路径/UTF-8/文件集合、哈希、跨目录身份、审核与正式发布区别等测试意图。纯搜索语义、来源大小写及版本失效用例迁移到新模型；旧路由、旧选择器、固定 HTML 结构断言随旧实现删除，不做机械照搬。

新增验证围绕风险：

- 依赖方向和无环检查，构建与浏览器入口分离。
- 同一 Markdown 在构建/运行时得到相同块模型；模式切换不改变身份。
- 查询取消、迟到响应、并发缓存、文档失败可重试。
- 阅读无需核验/反馈模块可用；工具失败有局部错误。
- 页面反复挂载/销毁不残留事件、计时器、观察器或旧任务。
- 原句/全部关键词的准入，候选/完整索引等价性；默认折叠不会丢命中。
- 精确版本进度恢复、更新/撤回失效、存储不可用、显式锚点与浏览历史优先级。
- 连续阅读多 P 追加、回看、缺号、末篇、单 P、同 P 两类版本和已确认系列。
- 正文/参照反馈身份隔离、暂存与剪贴板失败、Issue 长度边界。
- 桌面 1366 × 768 与宽屏、手机 390 × 844 与 320 × 768；长标题、无标签/摘要、无目录、空发布、待审核稿件和长正文。

统一 browser 测试入口，复用有效 fixture；真实快照用于最终任务抽样与加载测量。浏览器测试绑定用户可见行为和可访问名称，尽量不依赖内部 CSS 类。

最终执行内容验证、测试、边界检查、生产构建与生产预览回归。构建资产指纹有效、GitHub Pages 子路径可刷新与分享；旧 URL 和旧存储故意不兼容应作为新方案断言，不作为漏修。

## 12. 完成定义

必须同时具备新体验与新边界：目录/搜索的默认结果规模受控；阅读与核验解耦；状态有唯一所有者；构建不依赖前端页面；正文不依赖贡献工具；组件样式不再跨修复文件覆盖；旧实现、旧路由和存储迁移路径已清除。

README 更新为新运行、数据与页面契约；产品哲学同步说明导航入口、核验层级和阅读模式的最终取舍，历史交付说明继续作为历史记录，不用于声称新实现已完成。自动主题若未实施仍保留提案状态。

本计划阶段只新增本文档，不改变快照、不实现新前端、不部署。完成重构后以真实用户任务和对应测试结果验收，不以文件拆分数量作为解耦证据。
