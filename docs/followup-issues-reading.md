# 阅读问题第二轮修复记录

日期：2026-10-10。基线：`bb56105`，当前快照为 583 篇公开预览、478 个视频，正式发布目录为空。本轮使用独立 worktree 与 `codex/fix-reader-followup-issues` 分支。

服务对象为阅读哲学、人文长文的学习者、回找概念的复习者，以及中断后继续阅读的人。依据 [产品原则](product-philosophy.md) 的内容优先、辅助信息逐层展开、手机与键盘可用、位置与版本准确关联原则，优先修复查找与恢复阅读之间的冲突。

## 测量方式与边界

浏览器验证使用 Windows Chromium、生产构建与 `/markdown-reading-site/` Pages 子路径。本地预览结果不代表线上 CDN 性能，也不证明此前某次长时间等待的全部原因。

搜索样本为 `BV1Wh411y7Yr` 的“无意识中篇”单 P 查询。修复前 issue 报告的全类别索引为 16,446,017 字节解码正文、5,892,111 字节编码正文；当前分片的 Resource Timing 为 9,983 字节解码正文、4,282 字节编码正文、4,582 字节含响应头传输大小。局部查找只新增一个视频分片请求，热查询不新增索引请求。全局搜索的内容范围和索引保持完整，因此本轮未消除全局首次下载成本。

每种网络各测量 3 个独立上下文、禁用 HTTP 缓存的冷查询，随后在同页执行热查询。限速条件为延迟 150ms、下载 125,000 bytes/s（约 1Mbps）。记录加载、下载、解析、归一化、计算、渲染和总阶段；总阶段不含 120ms 输入防抖及浏览器绘制。

| 条件 | 冷查询总阶段 | 热查询总阶段 |
| --- | --- | --- |
| 本地正常网络 | 7.1–8.5ms | 0.6–0.7ms |
| 本地模拟限速网络 | 218.6–246.4ms | 0.4–1.2ms |

分片与全库索引复用相同的已校验正文块；构建产物同时包含这两种索引，增加了静态产物数量和总体大小，以降低局部查询下载量。未新增依赖，未修改冻结快照、正文、标签来源、审核与发布事实。

390×844px、浅色、无恢复提示的首段顶部测量如下；坐标以视口顶部为 0。完整原题保留，不用截断标题换取空间。

| 真实场景 | 修复前首段顶部 | 修复后首段顶部 | 首段可见行数 |
| --- | --- | --- | --- |
| 长标题单篇 | 770.5px | 630.5px | 5 行 |
| 多 P | 878.5px | 559.5px | 6 行 |
| 无意识中篇单 P | 653.5px | 513.5px | 3 行 |

恢复提示会占用约 142px，长标题场景带提示时首段可见约 2.16 行；未把这类情况写成无条件的三行保证。主题、来源、完整分 P 信息展开后仍会占用空间，默认首屏测量指它们收起时的阅读状态。

## 可重复验收

```powershell
pnpm test
$env:VITE_BASE_PATH='/markdown-reading-site/'
pnpm build
pnpm exec vite preview --host 127.0.0.1 --port 4179 --strictPort
playwright-cli -s=followup open http://127.0.0.1:4179/markdown-reading-site/
playwright-cli -s=followup --raw run-code --filename=scripts/check-tool-progress-browser.js
playwright-cli -s=followup --raw run-code --filename=scripts/check-scoped-search-browser.js
playwright-cli -s=followup --raw run-code --filename=scripts/check-followup-layout-browser.js
```

专项脚本分别覆盖正文进度/工具返回与首页继续、分片请求/31 处真实命中导航/IME/类别/限速，以及真实长标题和多 P 的首屏/完整标题标签/原文复制/到达提示。布局矩阵包含 320、390、1440px，浅深色和有无阅读恢复提示；另检查 200% 文本放大。

本轮单元测试 74 项通过，生产构建及 583 篇正文快照校验通过。既有浏览器回归脚本覆盖目录发现、全库搜索、正文阅读、连续阅读、视频查找、阅读历史、标题、布局、概览及错误重试。专项单元测试另检查类别隔离、元数据排除、来源段落顺序和 HTML 转义。人为改回全库 URL、移除命中类别隔离时，相关单元测试明确失败，恢复源码后通过。浏览器隔离上下文中移除工具打开时的进度保护监听者，专项明确复现第 16 段被第 1 段覆盖；实际源码与构建未受修改。

独立复审发现并修正了同页命中导航的历史恢复问题：新命中不能沿用离开前的滚动值；后退、前进恢复已保存位置时仍需重建命中高亮；原生 hash 历史事件不能在路由尚未加载时把位置覆盖成 0。浏览器自动滚动锚定在提示移除与工具栏重排期间可能抵消显式定位，因此只在这段布局变化期间暂停锚定，稳定后还原。专项浏览器检查加入第二处命中的后退、前进、精确位置、高亮、完整查询与结果展开恢复。

布局前后对照保存在 `artifacts/followup-baseline.json`、`artifacts/followup-acceptance.json`，上述搜索测量保存在 `artifacts/followup-scoped-benchmark.json`。浏览器测量 JSON 与截图写入本地忽略目录 `.tmp/`、`artifacts/`。它们是复核产物，不随内容快照导出；可用上述脚本重新生成。
