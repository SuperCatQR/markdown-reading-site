# 项目哲学与产品原则

本文件记录项目的长期产品定位、服务对象、设计原则与演进方向，是后续功能、界面、内容组织和技术选型的产品依据。由项目维护者于 2026-10-09 确认。

它描述目标与取舍，不代表列出的功能已经实现。当前实现与内容契约以代码、测试和 [README](../README.md) 为准。未来调整定位时，应同步更新本文件，说明改变的用户需求、依据与取舍。

## 1. 产品定位

项目是一个面向长视频与系列讲解内容的文字阅读资料库。它将视频讲解的整理稿组织为可搜索、可连续阅读、可回看来源的公开资料，服务学习、复习、查证与引用。

核心价值由四个动作构成：**阅读、查找、复习、核验**。

- 阅读：按照自己的速度理解内容，停下来思考，扫读或反复阅读某一段。
- 查找：通过概念、主题或记得的原句，重新找到相关内容与上下文。
- 复习：理解系列和分 P 的关系，持续学习，中断后继续。
- 核验：了解整理方式与当前状态，需要时返回原视频、校验参照和准确版本。

Markdown 是内容载体，独立前端是交付方式。产品表达应围绕内容和读者任务展开，读者无需理解主项目、转录工具或稿件生成流程即可使用网站。

以现有哲学、人文类系列讲解内容为起点，优先适配这类内容的学习者。结构可以扩展到其他课程、访谈或讲座；新的服务对象应有实际内容和用户需求支持。

## 2. 服务对象

以下画像是已确认的产品设计假设，需要通过实际使用持续验证；不应将其表述为已经完成的用户调研。

| 用户 | 典型任务 | 产品应提供的支持 |
| --- | --- | --- |
| 看过视频的复习者 | 找回某个概念、论证或原话 | 全文搜索、命中上下文、分 P 定位、来源回看 |
| 持续学习一个系列的人 | 按顺序阅读，分多次完成 | 系列目录、前后篇、阅读位置、继续阅读 |
| 更习惯文字的读者 | 自主控制阅读速度，或在不便播放声音的场景学习 | 内容概览、舒适排版、手机阅读、阅读设置 |
| 查证和引用者 | 做笔记、讨论、分享或保存资料 | 段落链接、来源信息、复制与下载、版本说明 |
| 校对贡献者 | 指出转录、专名或整理错误 | 校验参照、原视频、原句上下文、准确版本关联 |
| 内容维护者 | 导入快照，检查公开内容和状态 | 构建校验、状态展示、错误提示、可重复部署 |

前四类读者是主要服务对象；贡献者和维护者支撑内容质量与持续运营。普通阅读体验是默认入口，校验材料和技术详情按需展开。

## 3. 核心体验

完整体验应覆盖：

**知道这里有什么 → 找到适合的内容 → 理解所在位置 → 阅读 → 中断后继续 → 保存或分享 → 必要时核验与纠错。**

近期改动优先改善三个具体结果：

1. 进入网站能找到一讲。
2. 进入一讲能顺着读完，并进入相关的下一部分。
3. 离开后能回到上次阅读的位置。

每个功能应说明它改善了哪类用户的哪一步任务。仅增加页面、设置或视觉效果，不能替代对任务结果的解释。

## 4. 内容组织原则

### 4.1 按读者理解的关系组织内容

同一视频的多个分 P 应可辨认、可聚合，并按来源顺序导航。相同标题的列表项应明确显示分 P 信息，避免读者误认为内容重复。

目录标题直接进入正文，同视频分 P 切换与视频内查找在阅读页完成。单 P 内容不增加中转页面或重复导航；多 P 的连续阅读从当前正文显式开启。这一取舍依据维护者对实际使用的反馈，减少从找到内容到开始阅读的步骤。

视频、分 P 与跨视频系列是不同层次。已知的视频和分 P 信息可以直接用于聚合；系列归属、学习顺序与章节说明需要明确元数据或人工编辑确认。

“全部内容、系列、主题、最近阅读”是面向读者的组织方向。已发布与未发布仍需清楚区分，并提供准确状态与筛选入口。

### 4.2 来源与状态准确表达

展示内容来源、整理方式、人工复核情况及正式发布状态。审核通过与正式发布是不同事实，AI 初稿校验参照与当前编辑正文也应分别说明。

稿件整理质量与讲解内容的学术准确性是不同层次。审核标签应说明实际审核范围，不应暗示所有观点已获得学术认证。

正式发布内容为空时，应解释现状并提供明确的公开预览入口；预览稿仍保留其真实审核与发布状态。

### 4.3 内容元数据有依据

主题标签遵守现有内容契约，使用冻结 sourceMetadata.tags 中有证据的源视频标签；稿件编辑 tags 不充当来源主题；不从标题、编号或正文自行推断主题，不使用 AI 生成标签填补缺失值。

摘要、系列介绍、章节说明与学习顺序应作为有来源、可维护的编辑元数据输入。前端保留有来源的编辑摘要；正文只在读者主动查找时展示对应命中上下文，不用首段内容冒充摘要。

前端展示加工不得悄悄改写冻结正文、来源或审核事实。需要改善内容时，应沿上游编辑、审核和导出流程更新快照。

### 4.4 核验与反馈关联准确版本

校验参照、修改建议和引用信息应保留对应稿件的来源与版本关联。修改建议应带上原句、上下文、建议与理由，帮助维护者定位问题。

保存的阅读位置、批注或引用应能识别其对应内容版本。内容更新或撤回后，应明确处理旧关联，避免把旧批注或旧位置默认为新内容的准确位置。

## 5. 设计取向

采用**安静、清晰、有秩序的数字资料室**方向。“档案室”的表达、暖白或柔和深色背景、低饱和强调色与明确排版层级可以延续，实际可读性是判断依据。

- 内容优先：首页尽快呈现搜索、内容入口与可阅读资料，让读者在首屏开始使用。
- 中文阅读优先：在真实中文长文中检查字号、字体回退、行高、行宽与段落节奏；逐步提供阅读设置。
- 列表便于辨认：长标题、分 P、状态、来源和标签有明确层级，重要信息无需悬停才能发现。
- 状态用读者能理解的语言表达：说明是否人工复核、是否正式发布，以及对使用内容的影响。
- 辅助信息逐层展开：正文服务阅读，校验参照服务核验，版本详情服务追踪。
- 手机与键盘均可用：目录、筛选、前后篇和阅读设置适配小屏；保持可见焦点、合理对比度和触控区域。
- 动效帮助理解操作：提供清楚反馈，尊重减少动态效果的设置，以阅读与操作的稳定性为先。

界面效果应使用实际内容验证，尤其包括超长标题、同视频多分 P、空摘要、空目录、待审核稿件与长篇正文。

## 6. 功能演进方向

以下优先级用于指导取舍，是演进方向，不是完成状态或要求每次改动实现全部功能。

截至 2026-10-09，下表六项 P0 已在前端实现；范围、边界及验证方式见 [P0 阅读体验交付说明](p0-reading-experience.md)。P1、P2 仍是演进方向，目录会话状态恢复不等同于个人阅读进度。

后续内容发现功能已补充原句与多关键词反查、多个段落命中和阅读页内的视频搜索，见 [内容发现交付说明](discovery-experience.md)。独立视频总览已移除，目录直接进入正文，分 P 聚合导航由阅读页承载；将多个分 P 保留在同一阅读流中的连续阅读模式已实现，见 [连续阅读交付说明](continuous-reading.md)。本地正文进度与最近阅读已实现，准确版本关联、失效处理和当前浏览器保存范围见 [阅读体验修复交付说明](issues-reading-improvements.md)。2026-10-10 补充当前浏览器的字号、行距、行宽、字体设置与原文段落导览，见 [访客体验修复说明](visitor-experience-fixes.md)；收藏和跨设备能力仍未实现。

| 优先级 | 功能方向 | 用户价值 |
| --- | --- | --- |
| P0 | 清楚的首页介绍与内容入口 | 理解网站提供什么，发现当前可读内容 |
| P0 | 按视频聚合、分 P 标识、顺序导航 | 区分内容并连续阅读 |
| P0 | 搜索命中片段与关键词高亮 | 判断结果是否相关，定位上下文 |
| P0 | 返回目录保留搜索、筛选与滚动位置 | 阅读后继续探索，无需重新寻找 |
| P0 | 准确的来源、整理方式与稿件状态 | 判断内容应如何使用与核验 |
| P0 | 内容按需加载与搜索索引 | 内容增长后仍能快速进入和阅读 |
| P1 | 本地进度、最近阅读与收藏 | 支持多次访问和持续学习 |
| P1 | 字号、行距与阅读宽度设置 | 适配设备和个人习惯 |
| P1 | 段落分享、引用复制、Markdown 下载与打印样式 | 方便笔记、讨论和保存 |
| P1 | 选中文本后提出修改建议 | 降低纠错成本，保留准确上下文 |
| P1 | 编辑确认的系列说明与内容摘要 | 帮助选择内容与理解学习顺序 |
| P2 | 本地批注、笔记导出与已保存文章离线阅读 | 服务高频学习者 |

第二轮阅读改进补充了临时工具跳转保护、最近一篇的直接继续、按视频与类别加载的局部搜索索引，以及正文命中逐处导航，见 [第二轮修复说明](followup-issues-reading.md)。第三轮完成编辑确认系列的独立维护、导出、校验和阅读契约，改善全站搜索上下文及按查询加载成本，见 [第三轮修复说明](third-round-reader-fixes.md)。当前没有录入真实系列关联，内容关系仍需来源和编辑确认，不从标题或标签推断。

优先级可根据用户任务验证、内容条件和实现依赖调整。调整时应说明依据，并持续满足来源、版本、审核状态和静态快照契约。

## 7. 独立前端的边界

项目在运行时独立提供公开阅读体验，使用静态托管与经过校验的内容快照，不要求读者连接主项目或登录。

- 公开内容：由上游明确导出，经构建验证后交付。
- 浏览器交互：搜索、筛选、阅读和内容切换在前端完成。
- 个人状态：阅读设置、收藏、进度等保存在当前浏览器，提供适合其价值的导出与恢复方式。
- 外部反馈：修改建议通过 GitHub Issue 等明确入口交付维护者。
- 内容生产：编辑、审核、发布与撤回继续由上游流程执行，并通过重新导出和部署反映到站点。

“独立前端”允许构建时生成索引、预渲染页面与元数据。内容增长时，应将目录、搜索索引、正文与校验参照按用途组织和加载，避免进入目录就必须加载全部文档。

本地保存应清楚说明“保存在当前浏览器”，处理存储不可用或数据丢失的情况，不承诺跨设备同步。离线能力应明确缓存范围、版本和更新方式。

GitHub 反馈存在登录门槛。可以在站内先整理反馈文本，再提供预填 Issue 或复制文本入口；复制文本不代表建议已经提交。

账号、跨设备同步、公开评论、在线协作与共享批注需要额外服务。引入这些能力属于边界变化，需要明确用户价值、服务依赖与维护成本，并同步更新本文件。

如果将搜索引擎发现作为获客目标，应提供文章级标题、描述、可访问链接与可索引正文，并验证实际索引表现。静态预渲染可以支持这一方向，无需运行时后端。

## 8. 后续改动的决策与验收

涉及功能、界面、内容组织或技术选型的改动，应能回答：

1. 服务哪类用户，改善哪一个具体任务？
2. 用户在改动前后会有什么可观察的体验差异？
3. 是否保持来源、内容版本、审核与发布状态的准确表达？
4. 是否符合独立前端边界，并适配手机、键盘操作和实际内容规模？
5. 如何以与改动相称的方式验证结果？

对阅读和查找功能，优先用任务完成情况评估效果，例如：

- 读者能找回某个概念，并判断命中上下文是否相关。
- 读者能区分同视频的不同分 P，并按顺序进入下一部分。
- 读者返回目录后能继续之前的探索。
- 已实现本地进度时，读者再次访问能回到原有位置，并理解内容版本变化。
- 贡献者能提交带原句、来源和准确版本的修改建议。

验证方式应与改动影响相称。文档变更检查链接与一致性；交互改动验证实际任务；涉及内容契约的改动运行对应校验和测试。访问量可作辅助观察，任务是否完成是产品效果的主要依据。

2026-10-10 的多平台契约收口采用 universal-origin-v1（catalog v3/content v2/metadata v1/origins v1/manifest v2），拒绝旧消费格式；来源与稿件编辑字段分开，平台身份保留大小写，未知来源时间不由导入时间补齐。旧正文可由上游验证并保留迁移，必须展示真实 origin，不能冒充原生 AI v2；对应当前边界与验收见 [通用契约修复交付](universal-reader-delivery.md)。

## 9. 与其他文档的关系

2026-10-10 的阅读层级修复服务连续学习者、概念复习者与核验贡献者：固定显示稿件视图与阅读方式，将视频查找和来源移入独立工具面板，以实际可见分 P 更新分享地址，并为最近阅读提供独立视图。它落实“理解所在位置”和“按需核验”的既有原则，未改变内容生产及正式发布边界；逐项任务验证见 [阅读层级与切换修复](desktop-reading-hierarchy-fixes.md)。
