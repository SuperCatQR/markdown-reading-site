## 布局与文档结论

首页宣传段已按用户要求删除；独立专项记录 `.tmp/site-acceptance-responsive.log` 检查 320、390、900、901、1366、2048px，干净首页首个视频顶部约 337.5–355.5px，满足首屏开始使用。手机列表仍有横向溢出，故首页整体布局项失败；主脚本在 320px 首次失败时即结束该项，不用主 JSON 冒充后续视口证据。阅读页单 P、多 P 在 12 个布局组合中没有正文横向溢出；320px 正文宽 288px，390px 宽 358px，桌面遵循排版设置。此前“正文缩成窄列”的修复有效。

当前新模块已经隔开构建核心和部分服务，但 app 仍同时负责整页重画、阅读保存、查找、工具生命周期和恢复。搜索服务另写一套规则，绕过已有纯核心；页面内搜索只查当前 prepared blocks，不能代替计划中的同视频范围搜索。未见计划要求的 ReaderSession、NavigationSession、ProgressRepository 和严格跨层检查完整落地。**文件变少、入口切换和构建成功不能作为完全解耦成立的证明。**

README 与产品哲学仍引用旧交付文档中“连续阅读/准确恢复/上下文保留已实现”等历史结论。它们不能直接证明新入口保持了这些能力。修复时应更新当前能力说明、对应测试及重构状态；不能通过删掉产品要求让失败项变成通过。旧实现暂不删除，待新入口任务验收完成后再执行重构计划 G 阶段。

## 复现与再次验收

环境需要 Python Playwright 和 Chromium；脚本不会安装依赖或写入线上应用，只在独立浏览器上下文中操作本地存储及拦截请求。

```powershell
pnpm test
pnpm validate
pnpm build
pnpm exec vite preview --host 127.0.0.1 --port 5180 --strictPort
# 另一个终端：
python scripts/accept-site-browser.py --base http://127.0.0.1:5180/ --out .tmp/site-acceptance
```

脚本每项从干净上下文开始，包含真实导航、查询、滚动、设置持久化、503、损坏索引和本地记录。延迟测试等待整个请求完成/取消再检查页面，避免大索引尚在传输时产生假通过；故障注入用一次初始导航，避免 reload 的竞态干扰。失败输出 JSON、截图并以退出码 1 结束。

证据在本地 `.tmp/site-acceptance/report.json`、按项编号的 `*-failure.png`、`.tmp/site-acceptance-local.log`、`.tmp/site-acceptance-build.log`、`.tmp/site-acceptance-live/` 和线上日志中。截图及大日志不进入 Git。主脚本只支持当前真实快照样本，替换快照时需更新样本；它不是完整跨浏览器/安全测试套件。连续阅读与反馈项当前只检查入口，不能证明追加正文、反馈版本关联等完整任务；来源项检查可见 edition、URL 与 SHA-256 形状，准确值仍需和冻结快照核对。下一轮通过判定必须补足这些任务级断言。

修复顺序：先建立新入口行为回归和异步导航生命周期，关闭崩溃及进度破坏；再完成真实连续阅读、核验/反馈与返回会话；随后统一搜索语义、候选分片及资源预算；最后修正手机布局、键盘、对比度和文档。再次验收应关闭全部 P1、主脚本全绿，并补测浏览器返回、版本更新/撤回、工具失败、正文/参照身份隔离和分片等价性。当前站点不满足全量重构验收门槛。
