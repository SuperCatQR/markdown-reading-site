## 6. 关键实现约束与具体工作

### 6.1 搜索反馈与性能（#43）

涉及 [main.js](../src/main.js)、[directory-view.js](../src/directory-view.js)、[search.js](../src/search.js) 和按需索引加载器。

1. 首次查询立即展示“正在加载搜索资料”，结果区替换旧列表为清楚的等待状态；保留输入框和标签控件，避免 IME 上下文丢失。没有完成的元数据结果不得标作完整全文结果。
2. 较长等待补充简明说明和清空/取消本次查询入口；失败时明确重试。共享索引 Promise 同时服务目录和视频内搜索，不为取消一个查询中止其他消费者的请求。
3. 复用 `resultsVersion` / `renderVersion`，覆盖换词、清空、类别切换和离开页面。已有迟到保护应保留并扩大验证。
4. 分别记录请求开始至响应、下载、JSON 解析、检索计算、结果生成和 DOM 更新。缓存分为 HTTP 缓存与页面内 Promise 缓存；至少三次样本，注明设备、网络限制及索引身份。
5. 不为了显示“计算中”添加假延时；短同步计算保持输入响应，只有实测存在明显主线程阻塞时才评估 Worker。传输为主要成本时评估索引分片或明确标注的元数据先行，CPU 为主要成本时评估一次归一化缓存。派生数据仍在构建输出中，不写回输入快照。

### 6.2 首页与文章信息层级（#40/#47/#39/#46/#44）

涉及目录/阅读视图、[reader-details.js](../src/reader-details.js)、[ui.js](../src/ui.js)、[site.css](../src/site.css)。

- 首页保留一句用途、必要数量和真实状态，搜索与首条记录前移。页头分类仍可访问，但减少与“公开预览”指向同一集合的重复主操作；同时处理两类为空、仅发布、仅草稿及两类并存。
- 搜索方式采用原生可展开入口，默认收起；共享 `mode`、历史状态或当前非默认方式自动展开。综合、原句、关键词的匹配算法不因布局调整改变。
- 阅读顶部保留短而准确的当前状态、完整冻结标题和关键来源；详细处理说明集中按需展开。待审核、已审核但未发布和 AI 基线参照必须有区别，不能只剩一个无法解释的颜色点。
- 复制原始 Markdown、校验参照、精确版本和修改建议继续可访问；全文及编辑说明不做未经授权的重写。连续阅读复用来源组件，折叠逻辑需一并核对。
- 重要辅助文字以 13–14px 为设计起点，用真实中文与 200% 放大验证；维持正文 17px 手机基线及舒适行距。提高字号与压缩首屏靠删重复说明和重排实现，避免用更小字抵消占位。
- 完整长标题保留为实际可访问文本，不通过猜测标题前缀、术语或课程编号生成“核心概念”。单 P 减少重复数量说明；同 P 发布与草稿两版本不误当作两 P；搜索时保留命中数量与证据。

### 6.3 阅读中段工具（#42）

- 基于真实文章路由显示紧凑工具，分类入口保留在可展开区域；滚动状态变化不重新绘制正文，也不销毁当前焦点。
- 返回目录沿用原目录及保存条件；查找按钮打开现有视频内查找并聚焦输入；分 P 切换复用 `adjacentParts`，按当前类别和真实收录编号展示。
- 连续阅读的“当前 P”依据视口内实际阅读文章更新，不能只使用 URL 中最后一次选择的 P。单 P 不显示多余的前后部分。
- 固定区域高度、`scroll-margin-top` 与恢复偏移保持一致。有真实正文标题时复用目录，没有标题不生成章节。

### 6.4 最近阅读与准确进度（#41）

新增职责明确的本地进度模块，避免将持久化逻辑散落在目录、主题偏好及路由分支中。现有 [directory-state.js](../src/directory-state.js) 继续负责目录会话恢复；[continuous-reader.js](../src/continuous-reader.js) 暴露实际可见稿件和锚点信息。

- 记录至少包含：存储 schema 版本、稿件类别、`videoPartId` / BVID / P、edition、`contentSha256`、正文文件 `artifactSha256`、阅读模式、正文段落锚点、段内相对偏移和最后阅读时间。Release 身份在发布稿记录中保留；本地显示标题仅作缓存，不作为版本匹配依据。
- 以精确版本为恢复前提，段落锚点优先于整页 scrollY；固定工具高度及设备排版变化时重新计算。首次目标限制为正文，校验参照不覆盖正文进度，未来若支持参照需使用独立模式与文件哈希。
- 单篇与连续阅读统一记录当前可见部分。连续阅读重开只请求该部分，不为恢复旧 loaded 集合一次下载全部已读正文；route.entry 只是最后一次导航对象，不能直接代表读者滚回前文后的实际位置。
- 恢复优先级：显式分享锚点/搜索命中优先，浏览器历史恢复其次，本地进度以“继续上次位置”选择提供。读者已主动滚动或操作时，异步加载完成不再次强行跳转。
- 内容仍存在但版本改变，提示“内容已更新，可从新版开始”；撤回或缺失提示不可恢复，不自动把旧段落位置映射到新正文。草稿转发布也须重新核对文件与版本，不能仅凭同 BVID/P 静默跨版本恢复。
- 最近阅读默认保留有限记录（建议 20 项），支持删除和清空，说明“保存在当前浏览器”。存储拒绝、配额超限、损坏 JSON 或未知 schema 不阻止阅读；写入失败不可显示“已保存成功”。当前 `browserStorage` 会吞掉写入异常，进度存储需要能报告可用性。
- 滚动保存节流，路由离开与 `pagehide` 尽力保存；处理同浏览器多标签页更新和旧事件不得覆盖较新记录。没有账号、同步或 IndexedDB/Service Worker 的先验需求。

### 6.5 标签与排序（#48/#45）

- 标签链接通过 `URLSearchParams` 构造，保留源标签原名；从全部内容进入时可回到全部内容的标签筛选，直接打开时按稿件所属类别探索。明确这是一次新标签探索，旧查询不暗中限制新结果。
- 现有路由会拒绝完全不在当前快照出现的标签；内容更新后失效链接需有清楚的返回目录入口。目标类别没有匹配时显示空结果，不自动跨类别补内容。
- 标签从 `span` 改为 `a` 后同时更新样式、可见焦点和 `contrast.test.js` 的选择器，保持可读配色和链接语义一致。
- 无查询目录依据稿件创建/发布时间降序，分 P 数字顺序在组内；两类混合时它是稿件日期排序，不是统一意义上的“视频最新更新”或确认的课程顺序。
- 全文排序解释为正文证据优先、关键词同段覆盖优先、同分保持目录顺序；标题主要相关与仅提到概念分开评估。标题优先作为综合搜索可选项，不替代原句/关键词的全文准入条件。
- 如增加 `sort`，需同步 `searchRoute`、严格路由参数白名单、`sanitizeDirectoryState`、历史/session 保存、返回目录与链接往返测试；默认不变，按最高相关分 P 决定视频组位置，组内仍保持 P 与稿件类别顺序。

## 7. 验收、文档同步与完成定义

每个实现 PR 按影响运行 `pnpm test`、快照校验和 Pages 子路径构建。修复说明写清服务对象、改善的具体任务与相关产品原则；计划不代替交付证据。

浏览器验收矩阵：

| 维度 | 必须覆盖 |
| --- | --- |
| 页面与真实内容 | 长/短标题、空摘要、无目录/有目录、单 P、多 P、缺号、同 P 两版本、正文与参照、连续阅读 |
| 快照状态 | 两类均空、仅发布、仅草稿、两类并存；pending-review 和 approved 草稿均不称作正式发布 |
| 屏幕与交互 | 320/390px 窄屏、1440×900、深浅主题、200% 放大、键盘焦点、44px 主要操作目标、减少动态效果 |
| 搜索 | 标题与正文冲突、原句标点/空白、关键词跨段、多个段落、高亮和精确定位、中文 composition |
| 网络与历史 | 无缓存、页面内缓存、受控慢响应、失败重试、换词清空、离开、前后退、目录展开与滚动恢复 |
| 本地进度 | 新标签页/重开、正文版本变化、撤回/缺失、单篇与连续阅读、存储不可用/满/损坏、同浏览器多标签页 |

优先复用已有 `check-reader-browser.js`、`check-discovery-browser.js`、`check-reader-errors.js`、`check-reader-video-errors.js` 和 `check-continuous-browser.js`；补真正覆盖新状态和恢复行为的场景。纯文案和低影响样式无需逐行镜像测试。涉及搜索准入、版本匹配等条件的新测试，应通过反转关键条件确认能抓住回归。

交付时同步 README、产品哲学的已实现/待实施说明、相关交付文档与设计维护说明。#41 完成后方可将“本地长期进度待实施”更新为已实现；其他产品方向不顺带标作完成。修复分批提交，部署后复测真实站点；只有对应验收通过，issue 才具备关闭依据。GitHub 评论、关闭、标签调整及提交 PR 在执行阶段按用户授权处理，本次评估没有向外发送消息。
